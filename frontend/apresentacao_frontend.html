Slide 02

Camada de Domínio

O Coração Incorruptível — Regras puras, zero acoplamento a frameworks

  • Regras de Negócio Puras: As entidades Viagem (cálculos de percentualOcupacao e ultimasVagas), Reserva (estaFinalizada) e Usuario (ehAdmin) protegem as regras de forma cega, com acoplamento zero a frameworks ou rede.
  • Combate à Obsessão por Primitivos: Value Objects com construtor private e fábricas estáticas garantem o princípio do Fail-Fast (validação precoce).
  • Falha Semântica: Uso de erros customizados (EmailInvalidoError) para captura específica em vez de erros genéricos.
Código Real src/domain/value-objects/Email.ts 
import { EmailInvalidoError } from '../errors/EmailInvalidoError'

export class Email {
  private constructor(public readonly value: string) {}

  static create(raw: string): Email {
    if (!raw || !raw.includes('@') || raw.trim() !== raw || raw.length < 3) {
      throw new EmailInvalidoError(raw)
    }
    return new Email(raw.toLowerCase().trim())
  }

  toString(): string {
    return this.value
  }
}
Slide 03

Camada de Aplicação

Os Casos de Uso — Orquestração cega de tecnologias

  • Orquestração Cega de Tecnologias: Os Casos de Uso executam fluxos puros. Eles não sabem se a API é REST, GraphQL ou se o banco é SQL/NoSQL.
  • Inversão de Dependência (SOLID): O construtor recebe estritamente as INTERFACES dos repositórios definidas no domínio (IReservaRepository, IViagemRepository), nunca as classes concretas da infraestrutura.
Código Real src/application/use-cases/CriarReservaUseCase.ts 
import { Reserva } from '../../domain/entities/Reserva'
import { IReservaRepository, CriarReservaDTO } from '../../domain/repositories/IReservaRepository'
import { IViagemRepository } from '../../domain/repositories/IViagemRepository'
import { ReservaNaoAutorizadaError } from '../../domain/errors/ReservaNaoAutorizadaError'

export class CriarReservaUseCase {
  constructor(
    private readonly reservaRepository: IReservaRepository,
    private readonly viagemRepository: IViagemRepository,
  ) {}

  async execute(dados: CriarReservaDTO): Promise<Reserva> {
    const viagem = await this.viagemRepository.buscarPorId(dados.idViagem)

    if (viagem.estaEsgotada) {
      throw new ReservaNaoAutorizadaError('a viagem está esgotada')
    }

    if (dados.qtdVagas > viagem.vagasDisponiveis) {
      throw new ReservaNaoAutorizadaError(
        `quantidade solicitada (${dados.qtdVagas}) supera vagas disponíveis (${viagem.vagasDisponiveis})`
      )
    }

    return this.reservaRepository.criar(dados)
  }
}

Camada de Infraestrutura

A Fiação do Sistema — Wiring e encapsulamento de dependências

  • Design Sustentável: Uso do FetchHttpClient encapsulando o fetch nativo do navegador, eliminando dependências externas pesadas (como o Axios).
  • Container de DI (Wiring): O arquivo container.ts centraliza todas as instanciações de baixo para cima, garantindo o ciclo de vida Singleton das dependências e blindando a UI.
Código Real src/infrastructure/di/container.ts 
/**
 * Container de Injeção de Dependência — único ponto de wiring da aplicação.
 * Os hooks de presentation importam apenas as instâncias exportadas aqui.
 */
import { FetchHttpClient } from '../http/FetchHttpClient'
import { LocalStorageTokenStorage } from '../storage/LocalStorageTokenStorage'
import { ViagemHttpRepository } from '../repositories/ViagemHttpRepository'
import { ReservaHttpRepository } from '../repositories/ReservaHttpRepository'
import { CriarReservaUseCase } from '../../application/use-cases/CriarReservaUseCase'

// --- Infraestrutura base ---
export const tokenStorage = new LocalStorageTokenStorage()
export const httpClient = new FetchHttpClient()

// --- Repositórios concretos ---
export const viagemRepository = new ViagemHttpRepository(httpClient, tokenStorage)
export const reservaRepository = new ReservaHttpRepository(httpClient, tokenStorage)

// --- Casos de Uso ---
export const criarReservaUseCase = new CriarReservaUseCase(reservaRepository, viagemRepository)

Camada de Apresentação

Logic-Free UI & Open Code — JSX magro, componentes locais

  • Componentes Magros (JSX-Only): LoginPage delega 100% dos estados do React 19 e submissões para o Custom Hook useLogin (controlador puro).
  • Paradigma Open Code (Shadcn/ui): Componentes locais na pasta de código fonte usando React.forwardRef para repassar referências nativas do DOM e a função cn() (clsx + twMerge) para fusão inteligente de classes Tailwind.
Código Real src/components/ui/input.tsx 
import * as React from "react"
import { cn } from "@/src/lib/utils"

export interface InputProps
  extends React.InputHTMLAttributes<HTMLInputElement> {}

const Input = React.forwardRef<HTMLInputElement, InputProps>(
  ({ className, type, ...props }, ref) => {
    return (
      <input
        type={type}
        className={cn(
          "flex h-10 w-full rounded-md border border-input bg-background ...",
          className
        )}
        ref={ref}
        {...props}
      />
    )
  }
)
Input.displayName = "Input"

export { Input }

Estratégia de Testes

A Pirâmide Completa — DOM virtual, comportamento real, isolamento cirúrgico

  • DOM Virtual em Memória: O Vitest executa sobre o ambiente JSDOM, montando a árvore de componentes na memória do Node sem precisar abrir navegadores lentos.
  • Comportamento Real do Usuário: Uso do fireEvent para simular interações reais de preenchimento e clique, validando a ponte UI → Hook → UseCase.
  • Isolamento Cirúrgico: O vi.mock intercepta exclusivamente o container de DI, garantindo que o componente de tela e o Custom Hook useLogin sejam testados juntos em integração real.
Código Real app/login/__tests__/page.test.tsx 
import { render, screen, fireEvent, waitFor } from '@testing-library/react'
import { describe, it, expect, vi } from 'vitest'
import LoginPage from '../page'
import { loginUseCase } from '@/src/infrastructure/di/container'

// Mockamos apenas a Injeção de Dependência do Caso de Uso
// Assim, o componente E o custom hook (useLogin) são testados em integração real!
vi.mock('@/src/infrastructure/di/container', () => ({
  loginUseCase: { execute: vi.fn() }
}))

render(<LoginPage />)

fireEvent.change(screen.getByLabelText(/E-mail/i), {
  target: { value: 'maria@email.com' }
})
fireEvent.change(screen.getByLabelText(/Senha/i), {
  target: { value: '123456' }
})
fireEvent.click(screen.getByRole('button', { name: /entrar/i }))

await waitFor(() => {
  expect(loginUseCase.execute).toHaveBeenCalledWith({
    email: 'maria@email.com',
    senha: '123456'
  })
})
